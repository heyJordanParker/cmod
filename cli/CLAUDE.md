# Facts

- `mail.sqlite` in the cmod store holds each message between sessions until the session's cmod plugin takes it, and `openMail` in `src/serve.ts` is its one opener. It holds what no transcript holds, so a newer cmod never deletes it as it deletes an older `history-<n>.sqlite`, and a change to its shape migrates it in place under `pragma user_version`. `routeSessions` in `core/src/runtime/interfaces.ts` stores each `send` before it delivers it through the `$/act` every cmod plugin from 7.0.0 answers, marks it delivered only once that act answered, and delivers each session's mail one at a time, in id order, so a `$/hold` and a `send` never deliver one twice.
- `observe` in `src/observer.ts` is the one way the cmod program follows files, and its only `fs.watch`: a file event only hints, and each look compares every listed file's modification time and size with the last look, every `busyScanMs` for `quietAfterMs` after its start or a change and every `quietScanMs` after, because macOS drops file events under load. `cmod serve` observes a session's transcripts only while a `cmod/Sessions` `Change` listener's matcher names `part: 'messages'`, because a released cmod plugin listens to its own session with no matcher. `isStartedWithin` and a waiting `cmod program` in `src/commands/program.ts` follow the instance file with it, never `cmod/Programs`, because `cmod serve` itself starts as a service that way, as systemd's `Type=notify` reports readiness on `NOTIFY_SOCKET` and never over D-Bus. `isStartedWithin` passes no hint folder, because Bun 1.4.4 blocked the thread 0.3 to 6.4 s on a Mac to close a `fs.watch` while the suite wrote files, and up to 12.7 s to exit with one open.
- Every test file that spawns a process calls `setDefaultTimeout(spawningTestLimitMs)` from `tests/cmod.ts`, 60 s, and no test names its own limit, because Bun 1.4.4 resets the limit for each file and evaluates a shared module once per process, so a call inside `tests/cmod.ts` reaches only the first file of a `bun test` run. With every file at once on the built `cmod`, at load average 52 to 95 on a Mac, the slowest test took 26.9 s and the slowest file 59.5 s.
- The launcher, `bin/cmod`, runs a cmod it just downloaded with `CMOD_INSTALLED_VERSION` set, and `src/main.ts` then tells `cmod/Store` a `Change` of the plugins, because a newer cmod in the store has no other writer that tells, and `cmod serve` and `cmod watch` exit on that `Change` for the newer one.
