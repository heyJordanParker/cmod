# Facts

- Claude Code refuses an `$.http.fetch` answer over 4 MiB, as `refused: body of <n> bytes is over the 4194304-byte limit`, and the cmod plugin reaches `cmod serve` only through `$.http.fetch`. So `connectRpc` in `src/runtime/rpc.ts` polls with `?chars=<pollChars>`, and `rpcRoutes` answers that poll with at most `pollChars` characters, sending a larger message as `$/part` pieces the client joins. A poll without `chars`, from a released core, gets every waiting message at once, as before.
- `cmod/Store` and `cmod/Programs` are `cmod serve`'s own interfaces, so `Providers.serveProvider` in `src/runtime/interfaces.ts` reaches them with no listing, and its listener comes back after a `cmod serve` restart. A Change only says to read the stored file again, so every reader also reads at each connect: the cmod plugin through `onStoreChange` with no part, and the `program` job on its 5 s lease tick while it starts.
- `hearServe` in `src/runtime/bun.ts` is the one way a cmod process hears `cmod serve`: it registers its listeners on the first connect and replays them on each reconnect before it calls `heard` with no payload, so its caller reads the stored files again only once every listener is in place and no `Change` falls between the read and the listen. It also calls `heard` with no payload when its first connect fails and when it loses `cmod serve`, because `cmod serve` exits on a newer cmod it was just told about and drops each `Change` a listener had not yet polled.
